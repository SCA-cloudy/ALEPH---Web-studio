# Quiplet — 짤·카드 스튜디오

이미지 위에 위트 있는 한마디를 얹어 밈·카드·SNS 게시용 이미지를 만들고 파일로 내려받는 도구입니다.
순수 HTML/CSS/JS로만 되어 있고 서버·로그인·외부 API가 전혀 없어 정적 파일 그대로 배포하면 됩니다.

> **이름/테마 결정 기록**: 처음엔 작업용 가제 "짤·카드 스튜디오"와 기본 흰색 라이트 테마로 시작했지만,
> 이름 5안 + 로고 마크, 화이트가 아닌 라이트 테마 5안을 시안으로 만들어 비교한 뒤 **"Quiplet"**(위트있는
> 한마디(quip) + 작은 조각(-let))이라는 이름과 **"더스크 라벤더"** 테마(해질 무렵 하늘 같은 은은한 보라
> 톤)로 확정했습니다. 상단 말풍선+스파크 로고, `favicon.svg`, `styles.css`의 `:root` 색상, 다운로드
> 파일명(`quiplet-*.png`, `quiplet-templates.json`)에 모두 반영돼 있습니다.

## 로컬에서 열어보기

별도 빌드 과정이 없습니다. 아래처럼 정적 서버로 열면 됩니다(브라우저에서 `file://`로 직접 열어도
대부분 동작하지만, 일부 브라우저의 보안 정책 때문에 로컬 서버로 여는 것을 권장합니다).

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000/index.html 접속
```

## GitHub Pages로 배포하기

1. 이 폴더 전체를 본인 GitHub 리포지토리로 push 합니다(`index.html`이 리포지토리 루트 또는
   `docs/` 폴더에 있으면 됩니다).
2. GitHub 저장소의 **Settings → Pages**에서 배포 브랜치(예: `main`)와 폴더를 지정하고 저장합니다.
3. 몇 분 뒤 `https://<계정>.github.io/<리포지토리 이름>/` 로 접속할 수 있습니다. 이 주소를
   `SUBMISSION.md`의 "결과물 주소"에 채워 넣습니다.
4. `소스 주소`는 push한 커밋의 해시를 고정해서 적습니다. 예:
   `https://github.com/<계정>/<리포지토리>/tree/<커밋 해시>`
   (터미널에서 `git rev-parse HEAD`로 확인)

## 아이패드·태블릿 등 다른 기기에서 테스트하기

손글씨(펜/터치) 기능은 실제 펜이 있는 기기에서 확인해 보는 게 정확합니다. 두 가지 방법이 있습니다.

**방법 A — 같은 Wi-Fi에서 바로 열어보기(가장 빠름, 배포 전에도 가능)**

1. 이 폴더가 있는 컴퓨터에서 서버를 컴퓨터의 모든 네트워크에 열어 실행합니다.
   ```bash
   python3 -m http.server 8000 --bind 0.0.0.0
   ```
2. 같은 컴퓨터에서 그 컴퓨터의 로컬 IP 주소를 확인합니다.
   - macOS: `ipconfig getifaddr en0` (Wi-Fi가 다른 인터페이스면 `en1` 등으로 바꿔보세요)
   - Windows: `ipconfig` 실행 후 "IPv4 주소" 확인
3. 태블릿이 **같은 Wi-Fi**에 연결된 상태에서, 태블릿 브라우저 주소창에
   `http://<컴퓨터의 IP주소>:8000/index.html` 을 입력합니다(예: `http://192.168.0.12:8000/index.html`).
4. 서버는 터미널 창을 닫으면 꺼지고, 컴퓨터를 재시작하거나 Wi-Fi가 바뀌면 IP도 다시 확인해야
   합니다 — 매번 켜서 확인하는 용도로 적합합니다.

**방법 B — GitHub Pages로 배포 후 그 주소로 열기(계속 쓸 링크가 필요할 때)**

위 "GitHub Pages로 배포하기"대로 배포하면 `https://<계정>.github.io/<저장소>/` 주소가 생기는데,
이 주소는 태블릿을 포함한 어떤 기기에서도 인터넷만 되면 그대로 열립니다. 링크를 계속 쓰거나
다른 사람과 공유하고 싶다면 이쪽을 권장합니다.

두 방법 모두 아이패드에서는 Safari + 애플펜슬, 안드로이드 태블릿에서는 Chrome + S펜 등으로
"2. 문구"의 "+ 손글씨" 레이어에 바로 그려 보시면 됩니다.

## 편집 기록(히스토리) 패널

저장된 템플릿 목록 바로 아래에 "편집 기록" 패널이 있습니다. 이미지 로드, 문구 변경(입력을 멈춘
뒤), 위치·크기·색 변경(슬라이더/색상 선택을 놓았을 때)마다 순서대로 자동 기록되고, "현재 상태를
기록에 추가" 버튼으로 원하는 시점에 수동으로도 남길 수 있습니다(포토샵의 레이어/히스토리 추가와
비슷한 개념). 목록에서 예전 기록을 클릭하면 그 시점 상태로 편집기가 되돌아가 그대로 이어서 편집할
수 있고, 되돌아간 뒤 새로 편집하면 그 이후의 "미래" 기록은 정리되고 새 기록이 이어 붙습니다(포토샵
히스토리 패널과 동일한 동작). 이 기록은 템플릿과 달리 `localStorage`에 저장하지 않는 세션 한정
작업 흔적이라 새로고침하면 초기화되며, 계속 남기고 싶은 상태는 "템플릿으로 저장"을 이용합니다.
동작 검증: `python3 scripts/test_history.py`.

## 글꼴 선택 + 손글씨(직접 쓰기) 입력 방식

"2. 문구" 아래 글꼴 드롭다운에서 기본 굵은 고딕 외에 Noto Sans KR, Black Han Sans, Jua, Do Hyeon,
Gaegu, Nanum Pen Script(손글씨), Poor Story(손글씨) 중 고를 수 있습니다(Google Fonts를 씁니다 —
`index.html`의 `<link>` 태그이므로 인터넷이 되는 일반 브라우저에서는 그대로 로드됩니다). 이건
"타이핑" 입력 방식입니다.

문구는 레이어마다 입력 방식을 "타이핑"과 "손글씨" 중 고를 수 있습니다. "2. 문구"의 레이어 칩 옆
"+ 손글씨" 버튼을 누르면 손글씨 레이어가 새로 생기고, 그 레이어가 선택된 동안에는 왼쪽 컨트롤이
펜 색·굵기·"마지막 선 취소"·"이 레이어 지우기"로 바뀌면서 가운데 미리보기 캔버스 위에 직접 그릴 수
있게 됩니다. 마우스만 있어도 클릭한 채로 드래그하면 그려지고, 애플펜슬(Safari)·와콤 등 펜 태블릿이
있으면 압력값에 따라 선 굵기가 달라집니다 — 브라우저 표준 Pointer Events API 하나로 마우스·터치·펜을
모두 같은 방식으로 처리하기 때문에 별도 드라이버·SDK가 필요 없습니다. 1:1·4:5·9:16은 손글씨 레이어
안에서도 각각 독립적으로 저장되어, 어떤 캔버스에 그렸는지에
따라 그 비율의 결과 파일에만 반영됩니다. 손글씨 레이어도 문구 레이어와 똑같이 "+ 복사"로 복제하거나
삭제할 수 있고, 여러 개 둘 수도 있습니다(예: 손글씨 사인 + 타이핑 문구를 함께).

글꼴과 손글씨 내용 모두 템플릿 저장/JSON 내보내기에 그대로 담깁니다. 검증:
`python3 scripts/test_font_ink.py`, `python3 scripts/test_layers_effects.py`
(`TESTLOG.md`에 자세한 결과와, 이 개발 샌드박스가 외부 네트워크 제한 때문에 Google Fonts를 못 받아와
손글씨체 구분 테스트 하나만 여기서는 FAIL로 나오는 이유를 적어 뒀습니다 — 실제 배포 환경에서는 정상
동작합니다).

### 손글씨 인식(OCR) → 문구로 변환 (다국어 지원)

손글씨 레이어를 고르면 컨트롤 아래쪽에 "인식 언어" 드롭다운과 "손글씨 인식 → 문구로 변환" 버튼이
있습니다. **한국어+영어(기본)·한국어만·영어만·일본어·중국어(간체)·중국어(번체)** 중 쓴 손글씨에 맞는
언어를 고르고 버튼을 누르면 [Tesseract.js](https://github.com/naptha/tesseract.js)(브라우저 안에서만
동작하는 오픈소스 OCR 엔진, CDN에서 불러오며 서버로 이미지를 보내지 않음)가 그 언어의 인식 데이터로
손글씨를 읽어서, 인식된 글자를 새 "문구" 레이어에 타이핑한 것처럼 채워 넣고 바로 그 레이어를 선택
상태로 만듭니다. 이후엔 일반 문구 레이어와 똑같이 타이핑으로 고칠 수 있습니다(원본 손글씨 레이어는
그대로 남아 있어 다시 인식을 시도하거나 손글씨 자체를 계속 쓸 수도 있습니다).

> 처음에는 "한글이 아니어도 괜찮다"고 하셨지만, 실제로 한글 손글씨를 써보니 영어로만 인식돼서
> 불편하다는 의견을 받아 언어 선택 기능을 추가했습니다. 기본값은 "한국어+영어"이고, 여러 언어를
> 섞어 쓰는 경우가 아니면 정확도를 위해 해당 언어 하나만 고르는 것도 좋습니다(예: 일본어만 쓴다면
> "일본어"로).

Tesseract.js는 원래 인쇄체·스캔 문서 인식에 최적화된 엔진이라 자유롭게 휘갈겨 쓴 손글씨는 언어와
무관하게 정확도가 낮을 수 있습니다. 그래서 인식 결과는 항상 화면에 안내 메시지로 보여주고 사용자가
확인·수정하도록 설계했습니다. 언어를 처음 쓰면 그 언어의 인식 데이터(traineddata)를 추가로
내려받기 때문에 첫 인식은 조금 더 걸릴 수 있고, 이후엔 브라우저에 캐시되어 빨라집니다.

또한 이 개발 샌드박스는 외부 네트워크가 허용 목록 방식이라 엔진을 불러오는 CDN(`cdn.jsdelivr.net`)이
막혀 있어(`curl` 결과 403 Forbidden, Google Fonts 때와 같은 제약) 실제 인식 자체는 여기서 확인할 수
없습니다. 대신 (1) 엔진을 못 불러왔을 때 앱이 멈추지 않고 안내 메시지를 보여준 뒤 버튼이 다시
눌러볼 수 있는 상태로 돌아오는지, (2) 드롭다운에서 고른 언어가 실제로 `Tesseract.recognize()`
호출에 그대로 전달되는지(가짜 Tesseract 객체를 심어서 검증)를 각각 확인했습니다. 실제 GitHub Pages
배포 환경(일반적인 인터넷)에서는 엔진이 정상적으로 로드되어 실제 인식까지 이어지므로, 배포 후
언어별 정확도를 직접 확인해 보시는 걸 권장합니다. 검증: `python3 scripts/test_ocr.py`.

## 도형(하트·별·폭죽) 레이어

"2. 문구" 레이어 칩 옆 "+ 도형" 버튼을 누르면 장식용 도형 레이어가 새로 생깁니다. 하트·별·폭죽 중
고를 수 있고, 이미지·이모지가 아니라 Canvas 2D 경로(베지어 곡선, 좌표 계산)로 직접 그리는 **벡터
도형**이라 슬라이더로 크기를 크게 키워도 흐려지거나 계단 현상이 생기지 않습니다. 위치·크기·회전을
문구 레이어와 똑같은 방식(슬라이더)으로 조절하고, 색도 아래 "색상 컨트롤"과 동일한 것을 그대로
씁니다. 도형 레이어도 "+ 복사"로 복제하거나 삭제할 수 있고, 문구·손글씨 레이어와 자유롭게 섞어서
여러 개 둘 수 있습니다(예: 제목 문구 + 하트 두 개 + 손글씨 사인). "폭죽"은 정지 이미지 특성상
애니메이션이 아니라 중심에서 사방으로 뻗어나가는 빛줄기 형태의 장식 모티프로 표현했습니다.

## 색상 컨트롤(HEX / RGB / 그라데이션)

문구 색과 도형 색 모두 클릭하면 펼쳐지는 같은 색상 조정 패널을 씁니다. "단색" 탭에서는 `ffffff`
같은 6자리 색상 코드를 직접 입력하거나 R/G/B 숫자(0~255)를 각각 넣어서 정할 수 있고, 두 입력은
서로 실시간으로 동기화됩니다. "그라데이션" 탭으로 바꾸면 시작색·끝색과 각도(0~360°)를 정할 수
있고, 실제 다운로드 파일에도 그 그라데이션이 그대로 렌더링됩니다(레이어가 회전돼 있으면 그라데이션
방향도 함께 회전합니다). 색 값은 템플릿 저장/JSON 내보내기에도 그대로 담깁니다(단색은 문자열,
그라데이션은 시작/끝/각도를 담은 객체). 검증: `python3 scripts/test_shapes_and_color.py`.

## 화면 테마 (라이트 / 다크)

화면 맨 위 제목 오른쪽에 "☀️ 라이트 / 🌙 다크" 버튼이 있습니다. 편집기 화면(왼쪽 조작 패널, 가운데
미리보기 틀, 오른쪽 템플릿·기록 패널 등 앱 UI 전체)의 배색만 바뀌고, 만들고 있는 밈·카드 이미지
자체(캔버스에 그려지는 배경·문구·손글씨·도형)나 다운로드 파일에는 전혀 영향을 주지 않습니다(캔버스
둘레의 투명도 체크무늬는 다운로드 파일의 실제 투명 영역을 나타내는 표시라 테마와 무관하게 항상
그대로 둡니다). 선택한 테마는 이 브라우저에 저장되어 새로고침해도 유지되고, 처음 방문 시 저장된
값이 없으면 운영체제/브라우저의 다크 모드 설정을 따라갑니다. 검증: `python3 scripts/test_theme.py`.

## 위치(가로/세로) 슬라이더는 미리보기 바로 아래에

왼쪽 조작 패널에 회전·그림자·네온 같은 컨트롤이 많아지면 스크롤이 길어져서, 슬라이더를 움직이는
동안 가운데 미리보기가 화면 밖으로 벗어나 결과를 바로 확인하기 어렵다는 의견을 받았습니다. 그래서
문구·도형 레이어의 "가로 위치"·"세로 위치" 슬라이더만 왼쪽 조작 패널에서 떼어내, 가운데 미리보기
바로 아래("위치" 패널)로 옮겼습니다 — 원래 미리보기 칸 아래 비어 있던 공간을 활용한 것이라 전체
레이아웃(좌: 조작 / 중앙: 미리보기 / 우: 템플릿)은 그대로입니다. 손글씨 레이어는 캔버스에 그린
위치가 곧 결과라 별도 위치 슬라이더가 없고, 대신 안내 문구가 표시됩니다. 크기·회전·색 등 나머지
컨트롤은 지금처럼 왼쪽 조작 패널에 그대로 있습니다. 검증: `python3 scripts/test_layers_effects.py`
(`POSITION-panel-*` 항목).

## 화면 정리 — "+ 기능 추가"

기본 화면에는 이미지·문구의 핵심 컨트롤만 보입니다. 회전·그림자·네온은 "+ 기능 추가" 버튼을 눌러야
나오는 메뉴에서 필요한 것만 체크해서 씁니다. 체크하면 그 컨트롤만 펼쳐지고, 해제하면 다시 접혀서
(그림자·네온은 효과 자체도 함께 꺼짐) 화면이 복잡해지지 않습니다. 이 메뉴는 문구(타이핑) 레이어를
고르고 있을 때만 나타나며, 손글씨 레이어를 고르면 대신 펜 컨트롤이 나타납니다(아래 참고).

## 문구 레이어(복사) · 회전 · 그림자 · 네온

"2. 문구" 위에 있는 칩 목록이 지금까지 만든 레이어들입니다(문구 레이어와 손글씨 레이어가 섞여 있을
수 있습니다). "+ 복사"를 누르면 선택된 레이어를 그대로 복제해 새 레이어를 만들고(문구 레이어는
살짝 위로 옮겨서 겹치지 않게 보이도록 했습니다), 위/아래 문구가 있는 전형적인 밈 형식처럼 여러
문구를 독립적으로 편집할 수 있습니다. "+ 손글씨"는 타이핑이 아니라 직접 손으로 써서/그려서 넣는
레이어를 새로 추가합니다. 칩을 클릭해 레이어를 바꾸면 그 레이어의 값(문구 레이어면 문구·위치·크기·
색·글꼴·회전·그림자·네온, 손글씨 레이어면 펜 색·굵기·그려진 획)이 각각 그대로 불러와집니다.
"삭제"로 지울 수 있고, 레이어가 1개만 남으면 삭제 버튼이 비활성화됩니다.

"+ 기능 추가"에서 체크하면: 회전은 -180°~180° 슬라이더로 선택한 레이어를 그 중심으로 돌리고,
그림자는 색과 번짐 정도를 고를 수 있고, 네온은 지정한 색으로 은은하게 빛나는 글씨 효과를 냅니다.
전부 레이어별로 독립적으로 저장되고, 템플릿/JSON 내보내기에도 그대로 담깁니다. 검증:
`python3 scripts/test_layers_effects.py`.

## 템플릿 패널 위치

템플릿 저장/업데이트/JSON 내보내기·가져오기 버튼은 화면 오른쪽(저장된 템플릿 목록, 편집 기록과
같은 패널)에 모여 있습니다. 왼쪽은 지금 만들고 있는 문구·효과 조작에만 집중하도록 했습니다.

## 구현상 핵심 포인트

- **화면-파일 일치(카드2)**: 미리보기에 쓰는 캔버스를 그대로 `toBlob`으로 다운로드하기 때문에,
  화면에 보이는 픽셀과 다운로드 파일의 픽셀이 항상 동일합니다(별도 렌더링 경로가 없음).
- **파일 검증(카드1)**: 확장자가 아니라 파일의 실제 바이트(매직 넘버)로 PNG/JPEG 여부를 판별해서,
  확장자만 위장한 파일도 걸러냅니다.
- **템플릿(카드4)**: `localStorage`에만 저장됩니다. 서버가 없으므로 다른 사람과 공유되지 않고,
  이 브라우저에서만 유지됩니다.
- **위치정보 없음(카드5)**: 배경 이미지가 전부 코드로 그린 그라디언트/도형이라 원본부터
  EXIF·GPS 메타데이터가 없고, 캔버스로 다시 그려 내보내는 과정에서도 메타데이터가 생기지
  않습니다.
